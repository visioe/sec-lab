## 四、踩过的坑（按踩到的顺序）

| # | 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|---|
| 1 | PS 脚本不让跑 | `无法加载文件…未数字签名` | ExecutionPolicy=Restricted | `-ExecutionPolicy Bypass` 或 `Set-ExecutionPolicy RemoteSigned` |
| 2 | 管理员会话里没有 winget | `Get-Command winget` 失败 | winget 按用户安装 | 直接下安装包，别依赖 winget |
| 3 | VirtualBox `/S` 静默安装无效 | 没装上 | 装驱动要 UAC | 自提权 `Start-Process -Verb RunAs` |
| 4 | Kali 预构建镜像是「导入」 | `Could not find a registered machine named 'kali'` | 注册名是 `kali-linux-2026.3-virtualbox-amd64` | 从 `list vms` 正则取实名后 `modifyvm --name kali` |
| 5 | 挂光驱参数报错 | `Invalid --type argument 'dvdrw'` | 7.2 改了参数名 | 用 `--type dvddrive` |
| 6 | PS 5.1 把原生 stderr 当终止错误 | 脚本无故退出 | `$ErrorActionPreference='Stop'` | 封装 `VB` 函数，内部 `SilentlyContinue`，只看 `$LASTEXITCODE` |
| 7 | Kali 首次启动根目录只读 | `touch` 报 `Read-only file system`，DNS 全挂 | 镜像首启未 remount rw | `mount -o remount,rw /` 后重启 NetworkManager |
| 8 | 客户机改静态 IP 失败 | `settings plugin does not support adding connections` | NM 只启用 `ifupdown,keyfile` 插件 | 改在宿主侧做 DHCP 固定地址保留 |
| 9 | apt 装包 404 | `openssh-…13.19 404 Not Found` | ISO 自带索引过期 | `apt-get update`，并换清华 TUNA 源 |
| 10 | Ubuntu 桌面没有 curl | `找不到命令 curl` | 最小安装 | 用 `wget -qO-` 代替 |
| 11 | dpkg 锁被占 | `无法获得锁 /var/lib/dpkg/lock-frontend` | 桌面「软件更新器」在跑 | 停 `packagekit` + `killall aptd` |
| 12 | 宿主机 ping 不通客户机 | 100% 丢包 | Windows 防火墙默认丢 Host-Only 的 ICMP | 换 `Test-NetConnection -Port 22` 判定，或关防火墙 |
| 13 | Metasploitable 没有 Host-Only 地址 | `ifconfig` 只有 eth0 | 老系统 `/etc/network/interfaces` 只配了 eth0 | 手配 eth1 并写入配置文件 |
| 14 | Win11 鼠标点不准 | 点击落点漂移 | 指点设备是 PS/2 | `modifyvm --mouse usbtablet` |
| 15 | Win11 打不进字 | 键盘注入无反应 | 键盘设备是 PS/2 | `modifyvm --keyboard usb` |
| 16 | Win11 OOBE 强制微软账户 | 卡在登录页 | 26H2 移除了 `bypassnro` | `Shift+F10` → `start ms-cxh:localonly` |
| 17 | 输入被中文输入法吃掉 | 用户名变成「喇叭喇叭56」 | 微软拼音自动上屏 | 打字符前先按一次 `Shift` 切英文 |

## 五之二、RDP（3389）为什么开不起来

排查过程与结论，留档：

| 步骤 | 观察 | 结论 |
|---|---|---|
| 宿主机 `Test-NetConnection .30 -Port 3389` | `TcpTestSucceeded: False`，但 `PingSucceeded: True` | 网络层通，是服务没监听 |
| 靶机 `sc query TermService` | `STATE: 1 STOPPED` | 服务没启动 |
| 靶机 `net start TermService` | 「服务已经启动成功」 | 服务起来了 |
| 靶机 `netstat -an \| findstr :3389` | **无输出** | 服务在跑但**没有创建监听套接字** |
| 靶机 `(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server').fDenyTSConnections` | **`1`** | 根因：远程桌面被策略禁止，`TermService` 起来也不会监听 3389 |

**结论：`fDenyTSConnections` 必须为 0，`TermService` 才会 bind 3389。** 之前那条 `reg add` 虽然回报「操作成功完成」，但值没落成 0（大概率是 OOBE 会话里写入后又被 OOBE 的 RDP 状态覆盖）。

**可靠开关（图形界面，最不容易出错）：**
设置 → 系统 → 远程桌面 → 把「远程桌面」开关打开 → 确认。
Win11 会同时改注册表并放行防火墙的「远程桌面」规则组。

**命令行等价写法（管理员 CMD，注意引号必须完整）：**
```cmd
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 0 /f
net stop TermService /y
net start TermService
netstat -an | findstr :3389
```

> 注：RDP 对 D1 不是必需项——靶机的 `445 / 135 / 139` 已经开放，后续 SMB 方向的实验够用。RDP 主要用于「远程爆破 / 图形化横向」这类场景，D2 之后再补也不影响主线。

**最终结果（2026-11-10 22:50 实测）**：`3389 / 445 / 135 / 139` 全部 OPEN，快照 `02-rdp-enabled` 已固化。

## 五之三、一个会反复咬人的工具限制

`VBoxManage controlvm <vm> keyboardputstring` 单次发送**约 50 字符即被无声截断**，超长部分直接丢失。后果是命令被切成半截，而在 CMD 里半截命令会和下一行的残留拼在一起，产生"语法错误 / 变成了另一条命令"的假象。

规避方式：按 40 字符分段连续发送，最后统一补一次回车。这个坑在自动化装系统、批量下发命令时都会复现。
